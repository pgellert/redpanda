Task State Machine & Operator Controls

Reference for the cluster_link::task lifecycle and how operators drive it from rpk.

Two independent axes

AxisWhat it isSet byCode
enabledConfig flag: should this task run at all? is_enabled() returns _config.is_enabled Operator, via link configsource_topic_syncer.cc:222 etc.
stateRuntime status: active / paused / link_unavailable / stopped / faulted The task runner & reconcilermodel/types.h:162

"Pausing" is the enabled axis (paused: true ⇒ is_enabled()=false); the paused state is the runtime consequence of it.

The five states (and the docs' names)

Code stateDocs nameRunnerMeaning
activeACTIVEliveRunning & syncing normally
link_unavailableLINK_UNAVAILABLEliveCan't reach source — retrying every interval
faultedFAULTEDliverun_impl threw — still retrying on the timer
pausedPAUSEDdormantDisabled by config; runner torn down
stoppedNOT_RUNNINGdormantNot running here (e.g. lost leadership)
The load-bearing distinction: live states keep a runner alive whose timer re-arms after every run (task.cc:94-98), so they self-recover on the next successful run_impl. dormant states have no runner — only the reconciler's should_start can revive them, and it only fires from stopped/paused (task.cc:212-213).

Transitions

run_impl returns active (always allowed) ┌─────────────────────────◀─────────────────────────┐ │ │ ▶ active ──run_impl: source unreachable──▶ link_unavailable│ live: runner │ │ │ │ keeps ticking, │ │ run_impl throws ──▶ faulted ◀─────────┘ (throw) │ retries each │ │ │ └────run_impl ok───▶ active interval │ ▼ pause() / stop() ▼ (runner still alive) │ paused / stopped ◀── dormant: runner destroyed └────────── should_start (only from paused|stopped) ──┘

Validity rule (task.cc:341-352): link_unavailable is reachable only from active. Every other target state (active, paused, stopped, faulted) is always allowed.

Operator controls (rpk shadow)

Subcommands: create · update · describe · status · list · delete · failover · config generate. There is no pause/resume subcommand and no "restart task" command.

To pause/resume a task, edit the link config and apply it:

rpk shadow update <LINK_NAME> # opens config in $EDITOR (update.go:36) consumer_offset_sync_options: paused: true # ⇒ is_enabled()=false ⇒ reconciler calls pause() # save+close → rpk sends only the changed field paths (update.go:190-204)

Per-task flags live at types.go:146 (topic sync), :187 (consumer offsets), :199 (security). Inversion to watch: CLI/YAML says paused; core reads is_enabled = !paused (mapped mapper.go:227/262/282).

Unsticking a task: link_unavailable self-heals once the source is reachable — no action needed. To force a clean restart of a wedged/faulted task, the only rpk lever is a paused: true → update → paused: false → update cycle, which deterministically lands it back in active with a fresh runner. failover is unrelated (topic promotion, not task control).
