# SR Shadow Link POC — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Working in-tree vertical slice of Confluent SR → Redpanda SR replication as a `cluster_link::task`, with ID preservation, validation-rejection, mode/config replication, continuous tailing with <1s new-subject discovery, demoed via an extended ducktape test.

**Architecture:** New `schema_registry_replicator_task` under `src/v/cluster_link/` modeled on `group_mirroring_task`. Source-side: HTTP polling against Confluent SR using `src/v/http` with HTTP Basic auth. Destination-side: HTTP loopback to the local Redpanda SR using the standard SR wire format including `{"id": N}` for ID preservation. Subjects toposorted by references before write. Validation = local parse + dest POST result. Continuous mode = two-phase loop (catch-up then ~250ms tail).

**Tech Stack:** C++23, seastar, cluster_link::task framework, `src/v/http` client, `pandaproxy::schema_registry` types, ducktape (Python), Confluent Platform 7.7.1 in docker.

**TDD note (deviation from skill default):** This is a time-bounded overnight POC against a slow C++ build system. The *driving* test is the extended ducktape acceptance test (Task 14); pure-logic pieces (topo sort, regex filter) get unit gtests. Other tasks are commit-frequently-with-incremental-builds rather than per-micro-step TDD. This is called out explicitly so it can be tightened later if scope allows.

**Branch:** `slsr/poc` (already checked out, design doc + stash files already committed).

```cpp
#pragma once

#include "base/seastarx.h"
#include "cluster_link/deps.h"
#include "cluster_link/task.h"
#include "pandaproxy/schema_registry/types.h"

namespace cluster_link {

/// Continuously replicates the contents of a Confluent-compatible source
/// Schema Registry into the destination Redpanda SR via HTTP, preserving
/// schema IDs by driving the destination's IMPORT-mode path.
///
/// POC scope: HTTP Basic + plain HTTP, include-regex filtering, link-level
/// status. mTLS / bearer / context mapping / implicit-IMPORT / per-subject
/// status are deliberately deferred.
class schema_registry_replicator_task : public task {
public:
    static constexpr auto task_name = "Schema Registry Replication";

    schema_registry_replicator_task(
        link* lnk, const model::metadata& link_metadata);
    ~schema_registry_replicator_task() override = default;
    schema_registry_replicator_task(const schema_registry_replicator_task&) = delete;
    schema_registry_replicator_task& operator=(const schema_registry_replicator_task&) = delete;
    schema_registry_replicator_task(schema_registry_replicator_task&&) = delete;
    schema_registry_replicator_task& operator=(schema_registry_replicator_task&&) = delete;

    void update_config(const model::metadata& link_metadata) override;
    model::enabled_t is_enabled() const final;

protected:
    ss::future<state_transition> run_impl(ss::abort_source&) override;
    bool should_start_impl(ss::shard_id, ::model::node_id) const final;
    bool should_stop_impl(ss::shard_id, ::model::node_id) const final;

private:
    schema_registry_replication_config _config;
    // Set of subjects we believe are fully synced (subject name -> last seen high-water version)
    chunked_hash_map<pandaproxy::schema_registry::subject, pandaproxy::schema_registry::schema_version>
        _seen;
};

} // namespace cluster_link
```

### Task 9: Implement catch-up phase in `run_impl`

**Files:**
- Modify: `src/v/cluster_link/schema_registry_replicator_task.cc`

**Step 1**: Catch-up flow inside `run_impl`:
1. If `_seen` is empty: this is a fresh catch-up.
2. PUT /mode/{global} IMPORT on dest (idempotent; ignore "already in mode" error).
3. `GET /subjects` from source, filter by `include_regex`.
4. For each subject: `GET /versions`, then for each version `GET /schemas/ids/<id>` to get the full body.
5. Topo-sort.
6. Validate each locally; on fail, log warn, count, skip.
7. For each surviving schema: dest's `POST /subjects/X/versions` with explicit id.
8. Mirror per-subject mode + compat.
9. Populate `_seen`.

**Step 2**: Build, fix compile errors:
```bash
bazel build //src/v/cluster_link:cluster_link
```

**Step 3**: Commit:
```bash
git add src/v/cluster_link/schema_registry_replicator_task.cc
git commit -m "cluster_link/sr: implement catch-up phase

On first run, pull every filtered subject from the source SR, toposort
by references, validate, and write to the destination with explicit
IDs. Subsequent runs handle tailing only."
```

### Task 10: Implement tail loop with <1s discovery

**Files:**
- Modify: `src/v/cluster_link/schema_registry_replicator_task.cc`

**Step 1**: Tail flow (entered when `_seen` is populated):
1. Every ~250ms: `GET /subjects`, diff against `_seen.keys()`. New subjects get fetched + written immediately.
2. Every ~5s (counter-based): for each subject in `_seen`, `GET /versions` and replicate any version > last-seen high-water.
3. Mode/config drift: also revisited on the slow tick.

The task framework already runs `run_impl` on an interval; we use `set_run_interval` to switch between catch-up and tail intervals if helpful.

```bash
the new-subject discovery latency target."
```
